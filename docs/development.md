# Test ownership and repository contents

Production Java belongs to its deployable core, connector or format module. The shared Java test
corpus belongs to `streamfusion-runtime`; optional modules also keep their own tests. The parent
POM aggregates these modules and has no root `src/test` tree.

## Shared runtime tests

| Path | Responsibility |
| --- | --- |
| `streamfusion-runtime/src/test/java` | Common unit tests, SQL parity/recovery tests, reusable fixtures and existing benchmark programs |
| `streamfusion-runtime/src/test/java-flink1.18` | Test adapters and fixtures compiled only for Flink 1.18 |
| `streamfusion-runtime/src/test/java-flink2.2` | Test adapters and fixtures compiled only for Flink 2.2 |
| `streamfusion-runtime/src/test/resources` | Test SPI registrations, protocol samples, frozen recovery files and isolated Java compilation fixtures |
| `streamfusion-runtime/src/test/proto` | Protobuf inputs generated by Maven for runtime tests |
| `streamfusion-*/src/test` | Tests owned by the corresponding optional deployment module |

Maven uses its ordinary runtime-module Java and protobuf test paths. A build-helper source set
adds exactly one Flink line, and test resources also include the existing native retracting-rank
fixtures. The shared runtime test JAR supplies fixtures to optional connector tests without making
runtime depend on those connectors. This dependency direction keeps the reactor acyclic.
Rust compatibility tests include the same frozen state and ordering fixtures directly from the
runtime resource tree, so Java and native tests continue to check identical historical inputs.

The runtime corpus currently contains both module-internal and cross-module tests. It is not yet
split into separate unit-test, test-utility and benchmark artifacts. Moving the corpus preserves
Java packages, class names, methods, parameter providers, resource bytes and native/recovery
assertions. It does not change SQL admission, checkpoint formats or deployed artifacts.

```sh
mvn -pl streamfusion-runtime -am test
mvn -Pflink-1.18 -pl streamfusion-runtime -am clean test
```

Use clean outputs when switching Flink lines. The [CI guide](ci.md) describes ordinary runtime
shards, canonical restore inventories and native execution assertions. Shared test classes continue
to be discovered from `streamfusion-runtime/target/test-classes`; a source-directory move is not
permission to drop invocations from that inventory.

## Benchmarks and historical revisions

Existing benchmark Java remains in the shared test corpus in this delivery. The `bench` Maven
profile selects optimized native libraries; it does not authorize benchmark execution in CI.
Keep plan-only checks, including the Paimon TPC-DS planner selection, separate from performance
runs. A filename containing `Benchmark` is not sufficient to decide which contract it serves.

Core's optional Iceberg/Hudi benchmark profiles explicitly select fixtures and the matching Flink
test-context adapter from the runtime-owned tree. The historical JVM and nested-scalar comparison
tools read current fixture bytes from that tree and copy them into the actual shared test layout
of the immutable target checkout. Older
revisions still use root `src/test`; newer revisions use `streamfusion-runtime/src/test`. Unknown
or ambiguous layouts and missing fixture files fail before measurement instead of silently
producing an incomplete comparison. Recorded fixture paths name the destination checkout.

## Documentation and fixed inputs

Operator and connector pages describe current support. Benchmark reports describe their recorded
revision, configuration and measurement boundary. Follow the [evidence index](benchmarks/evidence.md)
for complete comparisons, component diagnostics, interrupted runs and rejected experiments.

Keep SQL inventory compressed snapshots, frozen protocol/state samples, structured measurements,
reproduction tools and design/rejection decisions in Git. In particular, legacy `.sst` and `.bin`
fixtures must retain their original bytes: regenerating them with the current writer would remove
the old-format compatibility check. A compressed filename alone does not establish that a file
can be deleted. Generated exports and historical raw logs/plans use the existing hash-verified
artifact workflow; see [evidence maintenance](benchmarks/evidence.md#maintaining-the-evidence).

## Remaining organization work

[#674](https://github.com/datafusion-contrib/StreamFusion/issues/674) tracks the subsequent steps:
extract a minimal test-utilities artifact, return module-internal tests to their owners, separate
benchmark compilation and split oversized documentation. Large historical JSON reports require a
versioned consumer/schema migration before embedded plans can become artifact references. Those
steps are independent of this physical source move; the current delivery does not claim their
completion or an improvement in test duration or SQL throughput.
